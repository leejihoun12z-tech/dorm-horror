# 고퀄 3D 배경 — 엔진 비교 · AI로 고퀄 맵 만드는 법

_작성 2026-11-27 · 사용자: "배경만 진짜 준AAA급(조명 포함)으로. Godot 그대로가 나아? 언리얼·유니티는 별로야? AI로 고퀄 3D 맵 만드는 방법 찾아봐"_
_캐릭터는 종이인형극 빌보드 [확정 방향](tech-plan §5-5-5). 엔진 Godot는 2026-11-25 [확정]이었고, 이 문서는 "준AAA 배경" 조건으로 다시 본 것. 결론은 [후보] — 사용자 확인 필요._

## 1. 결론
**Godot 유지 추천 — 단, "고퀄 복도 한 칸" 시험으로 확인한 뒤 굳힌다.**
- 우리 배경은 **좁은 실내 · 거의 움직이지 않는 공간 · 빛 몇 개 + 손전등**이다. 이런 공간의 "준AAA" 느낌은 엔진의 최신 기술보다 **미리 구운 조명 + 좋은 재질·소품 + 화면 마무리**에서 나온다. Godot는 이것을 다 갖고 있다.
- 언리얼이 사진 같은 그림을 가장 쉽게 내는 것은 맞다. 하지만 우리 상황(1인 · Claude가 코드와 검사를 자동으로 함 · 8GB 그래픽카드 · 2D 종이 캐릭터 · 실내)에서는 **얻는 것보다 잃는 것이 크다**.
- 시험에서 원하는 수준이 안 나오면, 그때 언리얼로 옮긴다. 지금은 코드가 적어서 옮기는 비용이 가장 싼 때다.

## 2. 엔진 비교 (2026-11 기준)
| | **Godot 4.7** (지금) | **Unreal 5** | **Unity 6** |
|---|---|---|---|
| 사진 같은 조명 | 미리 구운 조명(LightmapGI, GPU 굽기) · **4.7 새 사각형 면 조명(AreaLight3D) = 형광등 패널에 딱** · 4.6 반사(SSR) 전면 개선 · 볼류메트릭 안개 · 데칼 · HDR 출력(4.7). 움직이는 빛의 간접광(실시간 GI)은 약함 | **가장 강함**: Lumen(실시간 간접광)·Nanite·MegaLights. 손전등 빛이 벽에 튀어 방을 밝히는 것까지 자동 | HDRP는 **2026부터 새 기능 없음(유지만)**. URP에 실시간 GI를 넣는 중 |
| 약점 | TAA(계단 현상 줄이기)·AO(구석 그늘) 품질이 언리얼보다 낮음(Road to Vostok 개발자 지적) · 고퀄 자료·강좌가 적음 | 무겁다(편집기·빌드·그래픽카드) · Lumen이 움직일 때 번짐·잡음이 생긴다는 평 · 블루프린트는 Claude가 다루기 어려움 | 방향이 흔들림(HDRP 동결) |
| 비용 | 무료, 로열티 없음 | 무료, **한 게임 평생 매출 100만 달러 넘는 부분만 5%**(에픽 스토어 매출 제외) | Personal 무료(연 매출·투자 20만 달러까지), 넘으면 Pro 연 2,310달러/명 |
| 2D 종이 캐릭터 | 이미 만듦(`PaperPuppet`) | Paper2D·PaperZD로 가능, 다시 만들어야 함 | 가능, 다시 만들어야 함 |
| Claude 작업 | 글자로 된 씬·스크립트 → Claude가 직접 고치고 **클라우드에서도 실행·찍어서 확인** | 에셋이 이진 파일 · 클라우드에서 실행 불가 · MCP로 일부 조작 가능 | 중간 |
| 실제 예 | **Road to Vostok**(1인 개발, 유니티 → Godot로 옮김, 사실풍 FPS, 2026-04 앞서 해보기): "Godot도 사실풍 3D 됨, 사실감은 대부분 좋은 재질·구성·설정에서 나온다" | The Exit 8 등 사실풍 인디 공포 다수 | MiSide·Chilla's Art 등 |

**이 게임에서 언리얼이 꼭 필요해지는 경우:** 손전등 빛이 실시간으로 방 전체에 튀는 표현이 핵심이 되거나, 넓은 실외·많은 고밀도 모델이 필요할 때. 지금 계획(기숙사 실내·순찰)에는 해당이 적다.

## 3. AI로 고퀄 3D 맵 만드는 방법 4가지
| 방법 | 어떻게 | 품질 | 우리 게임에서 걸리는 점 | 판정 |
|---|---|---|---|---|
| **M1. 실제 공간 스캔 → 가우시안 스플랫** | 휴대폰으로 실제 기숙사 복도를 찍음(Scaniverse 무료·KIRI·Polycam) → 점 구름 모양 3D(스플랫) → Godot 플러그인 **gdgs**(MIT, Godot 4.3+, 충돌 생성·다시 비추기 v3.3) | 사진 그대로 | **찍을 때 빛이 그림에 굳어 있어 낮→밤 바꾸기가 어려움** · 스플랫은 그림자를 받지 못함(손전등 공포에 약함) · 실제 기숙사 촬영 허락 | △ 참고·먼 배경용 |
| **M2. AI 월드 생성** | 글·사진 → 3D 장면(World Labs Atlas/Marble: 스플랫 + 메시 + 충돌 내보내기 / SpAItial) | 그럴듯함 | M1과 같은 빛 문제 · 무료판 결과물은 상업 불가 · 방 배치를 원하는 대로 잡기 어려움 · **Hunyuan World는 한국 금지** | △ 콘셉트·참고 |
| **M3. AI가 돕는 일반 3D 제작** (추천) | ① Claude가 Godot·Blender 스크립트로 **모듈 키트 블록아웃**(벽·문·복도 치수) ② 재질 = 사진 스캔 CC0 재질(Poly Haven·ambientCG) + 직접 찍은 기숙사 사진 텍스처 + AI PBR 재질(필요할 때) ③ 소품 = 단순한 것(책상·사물함·신발장)은 Claude+Blender로, 특징 소품은 **Tripo Pro**(구독 중) → 면 줄이기, 흔한 것은 무료·구매 팩 ④ **조명은 사람이 감독** | 조명·재질만 좋으면 준AAA 실내 가능 | 손이 가장 많이 감 — 하지만 **낮/밤·손전등 그림자·이상현상 변화를 마음대로** 할 수 있는 유일한 길 | ◎ |
| **M4. 구매 에셋 중심** | 사실풍 실내 팩(Fab 등) + M3 조명 | 빠름 | 한국 기숙사다운 모습은 직접 손봐야 함 · 상품별 라이선스 확인(Godot에서 써도 되는지 [확인 필요]) · "NoAI" 상품은 AI 입력 금지 | ○ 보조 |

**실제 사례에서 나온 공통 교훈**
- AI 블록아웃 + 자동 배치는 시간을 크게 줄이고(공포 병원 맵 하루 제작 사례: 블록아웃의 약 70%, 흩뿌리기 80%를 AI가 함), **조명·이야기 소품은 사람이 해야 마지막 20%가 나온다**(같은 사례: 조명 60%를 사람이).
- AI 3D 소품은 면이 너무 많고 그림자가 색에 칠해져 나오기 쉬움 → 면 줄이기·재질 손질이 필요. 책상·의자 같은 단순 소품은 AI가 Blender에서 직접 만든 것이 오히려 쓰기 좋았다는 보고.
- 조명 원칙: "길을 찾을 만큼은 보이되 안심할 만큼은 아니게". 전부 어둡게가 아니라 **밝은 곳과 어둠의 경계**가 무섭다. 빛은 3종류로: 실제 광원(형광등·비상구) · 분위기 빛(창 밖 푸른빛) · 시선 끄는 빛.

## 4. Godot에서 "준AAA 실내" 만드는 구성 (M3) [후보]
| 층 | 쓸 것 |
|---|---|
| 조명 | 형광등 = **AreaLight3D**(4.7) · 간접광 = **LightmapGI**(GPU로 굽기, 방향 정보 켬) · 반사 = **ReflectionProbe**(한 번 굽기) · 손전등 = SpotLight3D 실시간 그림자 · 깜빡이는 등 = 굽기 모드 Dynamic |
| 공기 | 볼류메트릭 안개(옅게, 손전등 빛줄기) · FogVolume으로 구역별 |
| 표면 | 사진 스캔 PBR 재질 · 데칼(얼룩·테이프 자국·물 자국) · 왁스 바닥 반사 |
| 화면 | AgX 톤 매핑(4.6에서 조절 가능) · 색 보정 · 필름 입자 · 비네트 · (밤) 색 빼기 |
| 소리 | 형광등 웅웅·환풍기·먼 문소리 (배경 품질의 절반) |
- 낮/밤: 같은 공간에 **조명 세트 2벌**(낮 굽기·밤 굽기 또는 밤은 실시간 위주)로 바꾼다 [확인 필요: 라이트맵 2벌 메모리].

## 5. 다음 단계 — "고퀄 복도 한 칸" 시험 (PC, GPU 필요)
1. 참고 그림 3~5장 고르기(한국 기숙사 사진 + 화이트데이·The Exit 8·Chilla's Art 장면) → 목표 숫자(밝기·색) 적기.
2. 복도 6m + 방문 2개 + 사감실 문 + 소품 10개(신발장·소화기·게시판·우편함·분리수거함 등)를 M3로.
3. 낮(따뜻한 형광등) / 밤(손전등만) 두 벌 → 참고 그림과 나란히 찍어 비교 · 프레임 측정.
4. 종이인형 카드 1장을 세워 "실사풍 배경 + 종이 주민"이 어울리는지 확인.
5. 결과로 결정: **Godot 굳히기** 또는 **언리얼 시험**(같은 복도를 언리얼로 하루 만들어 비교).
- 이 클라우드 세션은 그래픽카드가 없어 라이트맵 굽기·고급 조명 확인을 못 함 → PC 채팅에서.

## 6. Godot vs Unity 다시 저울질 (2026-11-28) [후보 — 사용자 결정 대기]
_사용자: "godot이랑 유니티 다시 저울질해봐. godot 이해도가 있는 건 아니야, 완전 바이브코딩식이라 거의 없어."_
_새 조건: 배경 룩 = 회차가 갈수록 카툰 → 현실(리미널 형광) 섞기(look-exploration §10) · 엔진은 사용자가 아니라 **Claude가 거의 다 다룸**._

| 기준 | Godot 4.7 | Unity 6 (URP) | 이 게임에서 |
|---|---|---|---|
| Claude가 혼자 할 수 있는 범위 | 씬·스크립트가 글자 파일 → Claude가 직접 고치고, 창 없이 실행·화면 찍기까지 함(이 저장소에서 이미 씀) | 편집기가 켜져 있어야 함. 공식 MCP(2026-05 공개 베타, Unity 6+) · 커뮤니티 MCP로 조작 가능. 자산 들여오기·조명 굽기는 편집기 안에서 | **Godot 우세** — 사용자가 엔진을 모를수록 Claude가 끝까지 확인할 수 있는 쪽이 유리 |

| 비용 | 무료 | Personal 무료(최근 12개월 매출+투자 20만 달러 미만), 넘으면 Pro(2026-01부터 5% 인상) | 출시 초반엔 차이 없음 |
| 옮기는 비용 | — | 지금 Godot 코드 = 플레이어·시험 복도·종이인형·셰이더·검사 도구 정도 → 지금이 가장 쌈 | 늦을수록 비싸짐 |

- Claude 판단: **조금 Godot** — 엔진을 사람이 아니라 Claude가 다루는 방식에서는 "글자 파일 + 창 없이 실행·찍기"가 가장 큰 차이. Unity의 장점(Shader Graph·Asset Store·편집기에서 손으로 배치)은 **사람이 편집기를 만질 때** 커짐.
- 바뀌는 조건: 사용자가 편집기에서 직접 배치·조명을 만지고 싶다 / Asset Store 팩을 많이 사서 쓰겠다 / 유니티 편집기에 이미 익숙하다 → Unity.
- 정하는 법(추천): **같은 "카툰 → 현실 복도 한 칸"을 두 엔진으로 하루씩** 만들어 정지 화면 품질 + 사용자가 손댄 양을 비교 → 고름.

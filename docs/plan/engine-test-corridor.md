# 엔진 시험 — "카툰 → 현실 복도 한 칸" (Unreal · Unity, Godot는 기준)

_작성 2026-11-28 · 사용자: "Unreal·Unity 둘 다" (hq-environment-plan §6-2) · 결과로 엔진을 고른다. 모든 수치는 [작업값]._

## 1. 무엇을 보나
| 항목 | 재는 법 |
|---|---|
| 화질 | 같은 카메라 3자리(복도 끝 보기 · 방문 가까이 · 천장 형광등 아래)에서 **현실도 0 / 50 / 100%** 정지 화면 + 밤(손전등) 1장 → 세 엔진 나란히 |
| 섞기 자연스러움 | 현실도 0→100% 10초 영상 1개(중간이 탁해지는지) |

| 걸린 시간 | 시작 → 정지 화면 9장까지 |

## 2. 같은 조건
- 공간: 복도 6m × 폭 2.4m × 높이 2.6m, 양쪽 방문 4개, 끝에 방화문, 천장 형광등 패널 4개, 신발장 2·소화전함 1·게시판 1 (Godot 시험 복도와 같은 치수 `game/world/test_corridor.tscn`).
- 카툰 재질: 평평한 색 + 2~3단 그림자 + 외곽선 (룩 S49 서브컬처 카툰 렌더가 목표 그림).
- 현실 재질: **무료만** — Megascans(2026-11부터 무료, Fab Standard) · Poly Haven·ambientCG(CC0). 바닥 테라초·벽 페인트·문 나무·금속 소화전함 정도. 목표 그림 = 룩 S50 현실 끝판(초록빛 형광 리미널).
- 섞기: 재질마다 "현실도" 값 하나(0~1) + 빛 색(따뜻한 햇빛 → 초록 형광) + 화면 처리(노이즈·번짐)를 같은 값으로. 물건마다 따로 값을 줄 수 있게(조각씩 현실화, look-exploration §10 C안).
- 종이인형 카드 1장을 복도 가운데 세움(앞 그림만).

| 카툰 | 후처리 재질 또는 재질 함수 | Shader Graph 커스텀 조명 | 셰이더 코드 `light()` |

## 5. 결과

### 5-1. Unity 6.3 LTS URP (2026-11-28) — 정지 화면 `img/engine_test_20261128/unity_v2.jpg`
- 만든 것(PC `Projects/dorm-engine-test/DormLookUnity`, 저장소 밖): 셰이더 `Dorm/ToonRealBlend`(현실도 0 = 평평한 색 + 계단 그림자 + 외곽선, 1 = ambientCG 사진 재질 PBR, 전역 값 하나로 섞음) · `DormRealism`(빛 색 따뜻함 → 초록 형광 · 후처리 볼륨 카툰/현실/밤 가중치) · `DormBuilder`(복도 12m 짓기 + 카메라 3자리 × 현실도 0/25/50/75/100 + 밤 2장 = 21장 자동 촬영).
- 재질: Terrazzo008 바닥 · Plaster001 벽 · OfficeCeiling001 천장 · Wood003 문 · PaintedMetal005/012 · 창밖 = Poly Haven urban_courtyard_02.
- **Claude 혼자 된 비율**: 설치 뒤 편집기 클릭 0번. 사용자 몫 = 로그인 2번 · 약관 동의 답 3번 · 관리자 확인 창. 셰이더 오류 1번(Forward+ 조명 반복 매크로가 `inputData` 이름을 요구) → 한 번에 고침.
- 걸린 시간: 프로젝트 만들기 → 21장까지 약 25분(설치·다운로드 제외).
- 관찰(정지 화면, [작업값]): 0 → 100이 끊김 없이 이어짐 · 현실 100은 초록빛 형광 리미널로 꽤 그럴듯함(소품이 상자라 단조로움) · **카툰은 점광원 계단 그림자가 벽·천장에 큰 동심원으로 남아 거슬림** → 카툰 단계는 점광원 대신 면 빛/빛 웅덩이 텍스처로 바꿀 것 · 카툰 밤은 너무 밝고 손전등이 약함 · 현실 밤 손전등은 공포감 좋음.
- 빛은 굽지 않고 실시간만 씀(라이트맵 없이 비교). 굽기를 넣으면 현실 쪽 품질은 오르지만 현실도마다 따로 구워야 함.

### 5-2. Unreal 5.8.4 (2026-11-28) — 정지 화면 `img/engine_test_20261128/unreal_v1.jpg`
- 만든 것(PC `Projects/dorm-engine-test/DormLookUnreal`, 저장소 밖): 편집기 Python 스크립트 하나(`Scripts/dorm_build.py`)가 ambientCG 텍스처 가져오기 → 재질 `M_ToonReal`(현실도 = 재질 매개변수 모음 값 하나, 0 = 카툰 단색, 1 = 사진 재질) → 후처리 `PP_Toon`(빛 3단 계단 + 깊이·법선 외곽선, 현실도가 오르면 사라짐) → 복도 짓기(Unity와 같은 치수·재질표) → 카메라 3자리 × 21장 자동 촬영 → 편집기 종료.
- 빛: Lumen(실시간 간접광) · 천장 직사각형 빛 4개 + 천장 채움 점광원 · 창밖 Poly Haven HDRI.
- **Claude 혼자 된 비율**: 설치 뒤 편집기 클릭 0번. 사용자 몫 = Epic 로그인 · 약관 동의 답 1번. 설치는 런처 화면을 Claude가 눌러 진행.
- 걸린 시간: 첫 실행 → 21장까지 약 26분(설치 약 1시간 반 제외). 실행 6번, 고친 것 6개 — Python 이름 다름(`KismetMaterialLibrary` → `MaterialLibrary`) · `-ExecutePythonScript`는 스크립트 끝나면 편집기를 닫음(→ `-ExecCmds="py …"`) · 텍스처 칸 형식(노멀·마스크) · 후처리 HLSL 4성분 값 비교 · 레벨이 이미 있으면 새로 못 만들어 지난 실행의 빛이 쌓임 · 노출값.
- 관찰(정지 화면, [작업값]): 0 → 100 끊김 없음 · **카툰 외곽선이 Unity보다 깔끔**(화면 전체 후처리라 모든 모서리에 고르게) · **현실 100은 Unity보다 깊이감이 좋음**(Lumen 간접광으로 천장 어둡고 구석 그림자) · 현실 밤은 손전등 밖이 완전히 깜깜해 공포감 강함(조금 너무 어두움) · 카툰 밤 손전등은 계단 동그라미로 나옴(만화 느낌, 취향) · 점광원 동심원은 Unity와 같은 문제(채움빛 때문, 면 빛으로 바꿀 것).

### 5-3. 나란히 보기 — `img/engine_test_20261128/unity_vs_unreal.jpg`
| | Unity 6.3 URP | Unreal 5.8 |
|---|---|---|
| 카툰 끝 | 따뜻하고 진함(색 보정 값 차이) · 외곽선이 물체 껍데기라 가끔 끊김 | 중성적 · 외곽선 고르고 또렷 |
| 현실 끝 | 초록 형광 리미널, 평평한 편 | 간접광·그림자로 깊이감 더 좋음 |
| 밤 | 손전등 + 옅은 주변광, 읽기 쉬움 | 손전등 밖 깜깜, 더 무서움 |
| Claude 혼자 | 편집기 클릭 0번 · 셰이더 오류 1번 | 편집기 클릭 0번 · 오류 6번(대부분 API 이름·실행 방식) |
| 시간 | 약 25분 | 약 26분 |
| fps | 안 잼 | 안 잼 |

- 색감 차이(Unity 주황·Unreal 회색)는 엔진 차이가 아니라 이번에 넣은 빛 색·채도 값 차이. 두 엔진 다 값만 바꾸면 맞출 수 있음.
- **판단 [작업값]**: 정지 화면 고점은 Unreal 조금 우세(현실 쪽 깊이감·외곽선), Claude가 다루는 난도는 비슷(둘 다 편집기 손 안 댐). 남은 차이는 실제 걸어 다닐 때 느낌·fps·빌드 크기 → 사용자가 한 번 걸어 보고 정하는 게 맞음.
- 아직 안 한 것: fps 재기 · 현실도 0→100 10초 영상 · 종이인형 카드 세우기 · Godot 기준판.

### 5-4. 걸어 보기 (2026-11-28) — `img/engine_test_20261128/unity_walk.jpg` · `ue_walk.jpg`
- 여는 법(PC `Projects/dorm-engine-test/`): **`walk_unity.bat`** = Unity 실행 파일(창 1600×900) · **`walk_unreal.bat`** = Unreal 편집기가 열리고 복도에서 플레이가 자동 시작(편집기 화면 안, 화면을 한 번 클릭해야 마우스가 잡힘).
- 키(두 엔진 같게): WASD 이동 · 마우스 시선 · Space 점프 · 1~5 현실도 0/25/50/75/100%(천천히 바뀜) · Z/X 조금씩 · N 밤 · F 손전등 · Esc 끝(Unreal은 플레이 끝). Shift 숙이기: Unity는 누르는 동안, Unreal은 눌러서 켜고 끄기(5-5에서 추가).
- Unity: 1인칭 스크립트 `DormWalker`(새 Input System) · 장면 `Walk.unity` · 실행 파일 191MB(빌드 2분 반, 다시 빌드 15~40초). `-autotest`로 실행하면 스스로 낮·현실·밤을 찍고 끝남.
- Unreal: 엔진에 들어 있는 1인칭 템플릿(BP_FirstPersonCharacter·입력·팔 모델)을 복사해 씀 · 키는 `DebugExecBindings` → 편집기 Python `Scripts/dorm_live.py` 호출(개발용 방식, 실제 게임에선 블루프린트나 C++로 바꿔야 함).
- fps(1600×900 근처, RTX 5060): Unity 실행 파일 **약 350~480 fps** · Unreal 편집기 플레이 **120 fps에서 막힘**(편집기 상한, 현실도 0·100 모두 120 유지 → 실제는 그 이상). 공정한 Unreal 수치는 패키징 빌드를 해야 나옴.
- 고친 것: Unity 손전등이 11m 복도에 약함(세기 6 → 25) · Unreal 손전등이 저장된 낮 상태에서 "숨김"이라 세기만 올려선 안 켜짐(보이기도 같이 켬).
- 남은 것: Unreal 패키징 빌드 fps.

### 5-5. 사용자가 걸어 본 소감 (2026-11-28)
- 그림 품질: **Unreal이 나음**. 현실도 높은 밤: **확실히 Unreal이 나음**.
- 걷기: Unity가 나음 — Unreal은 너무 빨리 달림. 카툰↔현실 넘어가기: 둘 다 자연스러움.
- 고친 것: Unreal 걷기가 템플릿 기본 6 m/s(달리기 속도)였음 → **2.6 m/s로 Unity와 같게**(숙이면 1.2, 가속 1200·감속 1400, 점프 3.6 m/s) · 숙이기 추가(Shift 켜고 끄기, 눈높이 60cm 내림 — 템플릿 카메라가 팔 메시 head 소켓에 붙어 있어 팔 메시째 내림). 값은 [작업값], 다시 걸어 보고 고침.
- 판단: 걷기 차이는 값 문제라 고칠 수 있음 → 남은 차이(그림·밤)는 Unreal 쪽. **엔진 = Unreal 기울어짐 [후보]**, 사용자 확정 대기.
